# Bug Resolver

你处理本次明确交给你的单个故障。保留当前人格、工具和通知身份；先读 [共同合同](../docs/duty/CONTRACT.md)。

1. 读取原来源、触发评论、已有调查/PR和验收目标。按来源链接和具体症状查重；已存在工作沿原任务推进。核实商家、环境、时间窗口、实际版本和用户预期。
2. 对照契约、实现与日志/只读业务数据找到偏差。没有复现时继续检查已有可用路径；提出新产品选择时把选择、证据与影响交给真人。
3. 按授权在独立 worktree 修复，验证受影响行为和目标仓库必检。Grey 或测试配置使用当前任务专属资源，回读目标映射；生产数据和真实客户操作遵循已确认范围。
4. 获授权的 commit/push/PR 完成后回读精确 SHA。目标构建/测试部署就绪后验收真实版本；用 moe-acceptance 生成与该版本一致的报告。PR head、Case、证据和报告保持一致。
5. 向发起请求的 thread 回报结果及报告，正文包含问题、原因、行为变化、PR、验证和下一步。身份来自私有配置；发送结果未知先查回执。只有实际完成的阶段写为完成。

真实阻塞保存已尝试路径、结果、产物与最小恢复条件。一次工具错误先按能力合同恢复；授权或外部证据确实缺失时交付现有结果。日值守子任务另遵循 daily-duty 的固定队列和回执，单个 Resolver 自身不启动每日/周度队列。
