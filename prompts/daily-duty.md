# 每日 Bug 值守

保留当前 Agent 的人格与授权。先读 [共同合同](../docs/duty/CONTRACT.md)，涉及状态、登记或交接时读 [每日协议](../docs/duty/DAILY-PROTOCOL.md)。范围、来源、通知与时间窗口来自私有配置和本轮任务。

## 按入口执行

- `scan`：核对身份与固定脚本版本；按已批准的来源读取目标日，保存每源成功/失败回执；初筛、查重并冻结候选清单；登记两张调查工位卡，调用调度器。
- `investigate_lane`：先调度器 plan，只调查本工位当前 candidateId。核对正确行为依据、实现、数据和必要验证；上传/回读过程报告，追加本候选结论，然后 advance 交接。
- `investigate`：只恢复已登记的逐条调查协议，仍使用该轮固定版本。
- `resume`：回读原轮次、候选和启动 journal，仅补缺口；已停止轮次按真人决定处理。
- `bug`：全轮调查与覆盖门槛通过后，在固定修复队列内按 bug-resolver 完成一项。完整交付或受阻通知回读后，按计划器推进下一项。
- `gate_test`：仅在正文和 metadata 同时标明测试且目标为隔离项目时运行虚拟流程；虚拟证据、决定和通知维持测试标识。

## 调查口径

只修复正确行为有据、偏差可验证、范围明确的代码 Bug。产品取舍单独标记，已有在途工单/PR关联后去重；已合并修复仍须核对受影响版本与回归范围。公司/团队标签用于定位，实际范围以本轮配置为准。

候选必须有过程与结论：confirmed、duplicate、excluded、cs_followed、suspended_external 或调度器有限重试后的 skipped_failure。缺源、未调查、执行失败、真正缺外部材料分别记录。首次运行加最多两次重试后跳过的项保留三次 run、错误和恢复条件，继续处理其它候选。

## 调度与交付

每轮两张调查工位并行，汇总和修复串行，同一 Agent/项目全局只有一条修复队列。worker 只写自身报告与结论；父扫描汇总全轮、保存索引和修复清单。跨轮调查可继续，修复名额由 release-repair 交接。

报告覆盖全轮真实结论，包括跳过项和缺证项。修复中的正常构建等待继续按计划推进；真实阻塞保存原因与恢复条件，通知回读后释放队列。恢复受阻 Bug 复用原产物，保持队列游标单调。

采集结果、逐项交付、受阻结果和回告分别去重。生产发布先核对实际环境和版本；回告先起草，再按真人对精确内容、身份、接收人的批准发送。审查表情用于展示，返工/暂停/跳过以真实任务指令为准。
