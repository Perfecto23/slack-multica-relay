# 值守负责人通知

本协议只扩展已启用且已获通知授权的值守流程。保持现有执行 Agent、固定审查人、队列、并发和验收门槛。

1. 根据实际业务路径查询当前模块归属和 Component 到代码路径的权威记录，核对 Domain、Squad 与实际涉及的 FE/BE/PM/QA/EM。来源路径由部署者配置，旧身份表只用于定位。
2. 优先选择错误层对应的唯一模块 Owner；跨层问题只选实际涉及的角色。角色无法区分但 Domain 确定时，可选当前唯一 EM，注明业务接收联系人。归属或身份不确定时记录待核实，调查与修复继续。
3. 每个候选保存紧凑 ownership：状态、Domain、Squad、角色、联系人、选择依据、Slack user ID、身份核验状态、源记录 ID/版本/核验时间和证据引用。工位只写自身候选；父扫描汇总后传给修复任务，遵守 metadata 大小上限。
4. 发送前重读归属与有效 Slack 身份。在原有最终交付或真实受阻回报末尾附业务归属和去重后的联系人；使用 Block Kit 原生 user mention，dry-run 核对名单。中间态、技术失败跳过和零新增汇总保持原有接收人。
5. 记录 candidate/issue、结果版本、消息阶段、通知 user IDs 和写后回执。重跑复用已有回执，未知发送先回读。联系人核实失败只标注该缺口，保持原交付结果。

此协议只使用原有交付消息和目的地。Jira 指派、私信、额外频道、GitHub reviewer request 和历史补发各有独立授权；业务归属只说明接收职责。
